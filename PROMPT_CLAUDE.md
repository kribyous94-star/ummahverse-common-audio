# Prompt pour Claude — développer le POC UmmahVerse

Tu travailles dans mon dépôt UmmahVerse. Lis `SPECIFICATION.md` et `VALIDATION.md` ainsi que les scripts fournis avant de modifier quoi que ce soit. Inspecte l'architecture et les instructions du dépôt (`AGENTS.md`, README, conventions). Crée une branche dédiée si le dépôt est sous Git. Implémente et teste un POC utilisable de séparation audio multilingue **avec interface graphique de bureau fonctionnant sur Ubuntu et Windows**. Ne t'arrête pas à un plan ou à des fichiers vides ; produis le code, l'interface, la documentation, les tests et les commandes fonctionnelles. N'écrase pas mes changements préexistants. La rédaction de la documentation du projet et les commits Git font partie de ta livraison ; présente les commandes, les mesures et les identifiants des commits obtenus.

## Besoin exact

1. `extract` reçoit **deux fichiers audio** du même film, dans deux langues. Il produit `common.wav` (bande son commune estimée), `a_only.wav` et `b_only.wav` (résidus estimés), ainsi que `common.json` (alignement, gains, canaux, segments non comparables, confiance et version des paramètres).
2. La séparation doit également opérer **pendant les instants où le dialogue recouvre musique et bruitages**. Un simple détecteur de passages avec ou sans dialogue ne répond pas au besoin.
3. `subtract` reçoit `common.wav`, un troisième fichier audio et `common.json`. Après alignement et ajustement prudent du commun au nouveau mixage, il exporte `third_only.wav` et un rapport. Cette opération doit réutiliser le commun sans recalculer `extract`.
4. L'objectif ultérieur d'UmmahVerse est d'enlever la musique du `common.wav` avec mon outil existant, puis de recombiner les bruitages avec les dialogues. **N'implémente pas ce retrait musical dans le POC**, sauf intégration triviale déjà présente.

## Interface Ubuntu et Windows — livrable obligatoire

Crée une application de bureau locale en Python/PySide6, partageant **exactement le même moteur** que la CLI. Pas d'interface fictive ni limitée à Linux. L'écran en français permet de : choisir les deux fichiers A et B (sélecteurs de fichiers natifs, glisser-déposer si simple), choisir le flux audio quand il y en a plusieurs, sélectionner un dossier de sortie, lancer « Analyser / synchroniser », voir les avertissements de compatibilité/alignement, puis lancer « Extraire le commun et les résidus ». Un deuxième écran ou onglet permet de sélectionner `common.wav`, `common.json`, une piste d'une autre langue et son fichier de sortie, puis lancer « Soustraire le commun ». Afficher progression, annulation propre, erreurs compréhensibles, durée/état, accès aux fichiers produits et métadonnées de qualité. Le traitement long s'exécute hors du thread de l'interface ; la fenêtre doit rester réactive pendant un film. Les fichiers restent sur l'ordinateur et la mémoire doit rester bornée.

Sous Ubuntu, lancer avec `bash scripts/launch.sh`. Sous Windows, lancer avec `scripts/launch.bat` après `scripts/bootstrap.bat`, avec alternatives `.ps1`. Prévois les dépendances dans `pyproject.toml` (extra `gui` inclus par les scripts d'installation). Utilise `pathlib` et des appels à FFmpeg sans shell avec arguments séparés ; chemins Unicode, espaces et lettres de lecteurs Windows doivent fonctionner. Recherche `ffmpeg`/`ffprobe` dans le PATH ou via une configuration claire, affiche une erreur explicite s'ils manquent. Un exécutable autonome est facultatif pour le POC ; le lancement avec Python doit fonctionner sur les deux systèmes. Vérifie réellement les deux systèmes si disponibles, sinon documente précisément le test manuel restant sans revendiquer une validation Windows non faite.

## Rigueur technique attendue

Modèle de travail : `A = C_A + D_A`, `B = C_B + D_B`, avec `C_B` proche d'une transformation de `C_A`, et non nécessairement identique. Deux observations ne déterminent pas exactement trois sources arbitraires. Ne promets pas que « cohérence élevée = musique et bruitages » ; les mêmes mots, dialogues originaux en arrière-plan, sons de voix identiques et traitements du mixage peuvent aussi être communs. La cohérence Welch est une statistique moyennée sur plusieurs fenêtres, pas un détecteur parfait de source dans une seule case STFT. Une annulation adaptative peut aussi effacer une voix si elle est surajustée.

Implémente d'abord un **baseline mesurable**, puis une méthode améliorée si les tests montrent un gain : décodage sans perte et sélection explicite de piste via ffprobe/FFmpeg ; contrôle du montage et des canaux ; alignement global puis local à précision sous-échantillon si justifiée ; masquage des coupes ; estimation robuste du gain/filtre entre versions sur zones fiables ; extraction commune temporelle ou STFT complexe avec régularisation et lissage ; résidus calculés depuis le commun rendu dans chaque repère de piste. Ne remplace pas une perte d'identifiabilité par de la « reconstruction » non mesurée. Prévois le traitement par blocs d'un film complet et une mémoire bornée. Préserve le nombre et l'ordre des canaux quand ils sont compatibles ; refuse ou exige un choix explicite en cas de mono/stéréo/5.1 incompatibles ou de mapping inconnu. Ne fais pas de normalisation de volume séparée avant comparaison. Ne mélange pas automatiquement les canaux 5.1.

Les scripts dans `scripts/` définissent le contrat CLI, toujours disponible en plus de l'interface :

```text
python -m ummahverse_audio extract --input-a A.wav --input-b B.wav --out-dir output [--stream-a N --stream-b N]
python -m ummahverse_audio subtract --common output/common.wav --input C.wav --metadata output/common.json --output output/c_only.wav [--stream N]
python -m ummahverse_audio gui
```

Le `common.wav` est sur la base temporelle de A. Lors de la soustraction, synchronise et transforme le commun pour l'entrée C ; pour A et B, les résidus sont exportés dans leur base temporelle/documentée. Ne transforme le commun qu'avec des paramètres limités par les données fiables (par exemple fenêtres sans dialogue détecté) ; fournis la transformation appliquée et une confiance locale. Les sorties WAV doivent être flottantes ou PCM non saturées, et additionner le commun adapté + résidu doit reconstruire chaque mix de départ dans la zone comparable à l'erreur numérique près.
